## Interpretation boundaries

- Preserve supported capabilities. A reference example that names an unsupported operation is not authorization to invent a new geometry engine or cloud service.
- Generic sketch onboarding belongs to the existing reverse workspace. Scanner onboarding must explain measurement tasks, file units/scale, fitting versus raw points, confidence and saving. Runtime evidence determines where assistance is needed.
- The reference's illustrative unit switch changes labels only. Production continues to convert through the existing unit model.
- The reference's tiny/all-caps demo labels and breakpoint-hidden controls do not override its written minimum sizes or sheet-access requirements.
- Existing optional workspaces remain discoverable and respect the plugin contract. Do not violate plugin boundaries to make a unified-looking shell.
- Browser tests use owned profiles and ephemeral servers. No personal tabs, deployment, or upstream design PR is authorized. Physical pen/touch/SpaceMouse and unavailable browsers remain unverified.

## First-piece implementation checkpoint, 2026-10-31

The 3D Measure workspace now uses the supplied light tokens, top bar, workspace rail, project tree and resizable context dock. The four frequent fit actions plus More use existing measurement operations. Search invokes those same operations and explains prerequisites. Project and viewport use `selectedElementIds` in the existing Measure store. Rename is a real history action; selection alone does not create undo steps. No separate geometry model was introduced.

Editors retain their commit/cancel handlers and render their actions in a fixed footer. Export and Search can be visited without discarding an unfinished measurement. Medium layouts show one panel; phones use nonmodal bottom sheets. The first phone test reproduced an offscreen sheet caused by its grid positioning; the corrected sheet spans the grid. A short-height test caught footer overflow and resulted in an adaptive sheet height and footer layout. Page zoom is enabled. Reduced-motion camera transitions use the actual final pose immediately.

A generated, original 30 × 20 × 12 mm OBJ sample exercises the normal importer and fitter. Its caption follows display units; its source dimensions remain fixed. It is ideal geometry, not scanner-accuracy evidence. Existing hints remain. This is NOT a completed guided mode.

New `scripts/e2e-measure-design.mjs` exercises actual sample import, two face picks, 90° dimension, tree and viewport selection, F2 rename, visibility, exact extension, undo/redo, utility-panel draft retention, keyboard resizing, responsive layout and menu focus. Camera-motion and selection/history regressions also run in the unit suite. The test is part of the existing full browser gate. Final full gate at d87bdae passed 3,115 unit tests, 123 MCP tests, build and all available browser suites, including 40 dedicated Measure assertions. Private scan fixtures were skipped. Production sample loading passed desktop and phone. Startup medians were 1,984.2→1,926.7 ms (default) and 1,950.7→1,931.7 ms (plugins=none), three cold runs per mode. Initial encoded resources grew 8,581 bytes (0.78%). These small shared-Mac samples do not establish a speed improvement. Raw results: reference/measurements/design-build-01.json.
